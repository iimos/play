# `super_*_latest` — снимок открытой (текущей) 5-минутной суперсвечи

Основные суперсвечи (`tr.super_eq` / `tr.super_fo` / `tr.super_fx`) пишутся
только по завершении интервала. Чтобы видеть **незакрытую** пятиминутку, рядом
ведутся отдельные таблицы-снимки того, что API отдаёт по флагу `latest=1`.

| Закрытая (история) | Открытая (снимок) |
|---|---|
| `tr.super_eq` | `tr.super_eq_latest` |
| `tr.super_fo` | `tr.super_fo_latest` |
| `tr.super_fx` | `tr.super_fx_latest` |

- Источник: MOEX AlgoPack SuperCandles, `.../{eq,fo,fx}/{tradestats,obstats,orderstats}.json?date={today}&latest=1`
- Периодичность опроса в watch-режиме: **~20 секунд**
- Глубина: только **текущая** пятиминутка (одна строка на инструмент)

Колонки-метрики полностью повторяют соответствующие `tr.super_*` (описание
полей — в [supercandles.md](./supercandles.md) и `sql/tables.sql`). Отличия:

- добавлена колонка `updated_at` — время загрузки снимка (`DEFAULT now()` на
  стороне ClickHouse);
- движок `ReplacingMergeTree(updated_at)`, `ORDER BY (secid)`: в таблице живёт
  **одна строка на инструмент**, новая публикация того же `secid` вытесняет
  предыдущую по версии `updated_at`;
- устаревшие версии строк вычищаются загрузчиком (см. «Очистка»).

## Поле `updated_at`

`updated_at` заполняется автоматически (`DEFAULT now()`) в момент вставки
снимка. Это версия строки в `ReplacingMergeTree`: более поздняя публикация того
же `secid` вытесняет более раннюю. Значение отражает время **нашей загрузки**,
а не время расчёта среза на бирже (которое в данном датасете не используется).

## Важные нюансы

### 1. Читать через `FINAL`

`ReplacingMergeTree` схлопывает дубликаты по `secid` только при фоновом merge,
поэтому «одна строка на инструмент» гарантируется лишь при чтении с `FINAL`:

```sql
SELECT * FROM tr.super_eq_latest FINAL;
```

Без `FINAL` можно увидеть несколько версий одного `secid` (сырые вставки).

### 2. Очистка устаревших версий

После вставки снимка загрузчик удаляет строки с `updated_at` старше ~5 минут
(`ALTER TABLE ... DELETE`, `WHERE updated_at < now() - INTERVAL 300 SECOND`).
Так таблица не накапливает старые версии, а инструменты, исчезнувшие из
`latest=1`, пропадают из снимка не позже чем через ~5 минут.

Окно держится с запасом (период обновления ~20 с): если тик пропущен или
источник на мгновение вернул меньше строк, актуальный снимок не пропадёт —
`FINAL` покажет свежую версию из уже загруженных за последние 5 минут.

В таблице без `FINAL` при этом присутствуют версии за последние 5 минут (до
~15 батчей) — это норма, читать следует через `FINAL`.

### 3. Рассинхрон источников на границе интервала

`tradestats`, `obstats` и `orderstats` публикуются с разными лагами и могут в
один момент отдавать **разные** `tradetime` (например, вне сессии `obstats`
зачастую отстаёт на один интервал). Слияние идёт по точному ключу `(time,
secid)`, поэтому у разных инструментов в снимке может быть разное время, а у
инструментов, присутствующих только в одном источнике, — заполнена лишь часть
полей. В активную сессию рассинхрон краток; в неторговые периоды `time` отражает
последний интервал каждого источника.

### 4. Покрытие инструментов различается

Например, `fo/obstats` отдаёт заметно больше инструментов, чем `fo/tradestats`
(у инструментов без сделок есть стакан, но нет tradestats). Поэтому в
`super_fo_latest` у части инструментов заполнены только поля стакана.

### 5. Пустой ответ не затирает снимок

Вне торговой сессии или в неторговые дни эндпоинты могут вернуть 0 строк
(особенно `fx`). Загрузчик в этом случае пропускает обновление и **не трогает**
предыдущие строки — старый снимок будет заменён при первом же непустом ответе.

## Примеры запросов

Актуальный снимок по инструментам (топ по обороту):

```sql
SELECT secid, time, updated_at, pr_close, pr_change,
       round(val, 0) AS val, disb
FROM tr.super_eq_latest FINAL
ORDER BY val DESC
LIMIT 20;
```

Свежесть данных по рынкам:

```sql
SELECT 'eq' AS market, max(updated_at) AS last_update, count() AS instruments
FROM tr.super_eq_latest FINAL
UNION ALL
SELECT 'fo', max(updated_at), count() FROM tr.super_fo_latest FINAL
UNION ALL
SELECT 'fx', max(updated_at), count() FROM tr.super_fx_latest FINAL;
```

Сравнение открытой свечки с последней закрытой (`super_eq`):

```sql
SELECT 'closed' AS kind, time, pr_close
FROM tr.super_eq
WHERE secid = 'SBER' AND toDate(time) = today()
ORDER BY time DESC LIMIT 1
UNION ALL
SELECT 'open', time, pr_close
FROM tr.super_eq_latest FINAL
WHERE secid = 'SBER';
```
